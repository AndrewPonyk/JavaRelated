# Geospatial Analytics Platform

Enterprise GIS application using FastAPI, PostGIS, GeoServer, React, Leaflet, Mapbox GL-ready configuration, Deck.gl, and deterministic land-use classification over stored spatial features.

## Features

- Dataset CRUD.
- GeoJSON feature creation and import.
- PostGIS-backed bounding-box, proximity, and summary analysis.
- Layer catalog CRUD for WMS, WFS, Deck.gl, and classification layers.
- Classification job lifecycle with persisted metrics and artifact URIs.
- User and role administration.
- JWT bearer authentication support with local development auth disabled by default.
- React map UI with loading, error, validation, and responsive states.

## Run Locally

Copy the environment template:

```powershell
Copy-Item .env.example .env
```

Start the full stack:

```powershell
docker compose up --build
```

Default endpoints:

- Frontend: `http://localhost:5173`
- Backend API: `http://localhost:8000`
- OpenAPI docs: `http://localhost:8000/docs`
- API health: `http://localhost:8000/health`
- GeoServer: `http://localhost:8080/geoserver`
- PostGIS: `localhost:5432`

When running the backend directly on the host instead of through Docker, change `DATABASE_URL` to use `localhost` instead of the Compose service name `postgis`.

## Run Tests

Backend tests expect a PostGIS database. With Docker Compose running:

```powershell
cd backend
pip install -r requirements.txt
pytest
```

Coverage gate used by CI:

```powershell
pytest --cov=app --cov-report=term-missing --cov-fail-under=80
```

Frontend tests:

```powershell
cd frontend
npm install
npm test
npm run build
```

## API Surface

OpenAPI is generated by FastAPI at `/docs` and `/openapi.json`.

Primary route groups:

- `/api/v1/datasets`
- `/api/v1/datasets/{dataset_id}/features`
- `/api/v1/layers`
- `/api/v1/analysis`
- `/api/v1/classification-jobs`
- `/api/v1/users`

Example dataset creation:

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/v1/datasets -ContentType "application/json" -Body '{
  "name": "City parcels",
  "description": "Operational parcel layer",
  "source_type": "vector",
  "metadata_json": {"srid": 4326}
}'
```

Example point feature creation:

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/v1/datasets/<dataset-id>/features -ContentType "application/json" -Body '{
  "properties": {"land_use": "urban", "name": "Sample point"},
  "geometry": {"type": "Point", "coordinates": [30.5234, 50.4501]}
}'
```

## Authentication

Local development uses `AUTH_ENABLED=false`, which grants a development principal with `admin` and `analyst` roles. Set `AUTH_ENABLED=true` and configure `JWT_ISSUER`, `JWT_AUDIENCE`, and `JWT_SECRET` to require HS256 bearer tokens.

## Deployment

The GitHub Actions workflow lints, tests, builds both container images, and validates the Compose bundle. Production deployment should provide secrets through AWS Secrets Manager or Systems Manager Parameter Store and use an ALB or reverse proxy for TLS termination.

## Troubleshooting

- Docker error about `dockerDesktopLinuxEngine`: start Docker Desktop before running Compose.
- Backend cannot connect to the database from Docker: confirm `DATABASE_URL` uses host `postgis`.
- Backend cannot connect to the database from the host: use host `localhost` in `DATABASE_URL`.
- Backend integration tests are skipped when PostGIS is unavailable.
- Production startup fails with `ENFORCE_HTTPS`: set `ENFORCE_HTTPS=true` for production and terminate TLS at the load balancer or reverse proxy.
- Authentication startup fails: when `AUTH_ENABLED=true`, `JWT_SECRET` must be at least 32 characters.
