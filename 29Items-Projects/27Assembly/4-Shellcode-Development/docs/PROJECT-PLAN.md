# Project Plan: Shellcode Development

> Generated by **GLM-5.2**. Educational security-research / CTF toolkit for
> writing, encoding, and testing position-independent x86-64 Linux shellcode.

## 1.1 Project File Structure

The original "App Architect" prompt shipped a generic web-app template
(frontend / backend / database migrations / cloud pipelines). **None of that
applies to a NASM + pwntools project**, so this plan keeps only the components
relevant to the actual tech stack and marks the web-only sections as N/A.

```text
/
├── docs/
│   ├── PROJECT-PLAN.md        # This file — structure & roadmap
│   ├── ARCHITECTURE.md        # Pipeline/toolchain pattern + Mermaid
│   └── TECH-NOTES.md          # CI/testing/deploy/pitfalls
├── src/
│   ├── shellcode/
│   │   ├── execve.asm         # execve("/bin/sh") payload
│   │   ├── readflag.asm       # open/read/write payload (dumps flag.txt)
│   │   └── utils.inc          # Shared NASM macros (null-free)
│   ├── target/
│   │   └── vuln.c             # Deliberately vulnerable teaching target
│   └── scripts/
│       ├── exploit.py         # pwntools exploit harness (local/remote)
│       ├── encoder.py         # XOR encoder + null-free self-decrypting decoder
│       └── gen_reverse_shell.py  # Null-free connect-back generator
├── tests/
│   └── test_shellcode.py      # pytest: unit + integration + e2e (Linux)
├── .github/workflows/
│   └── ci.yml                 # build shellcode + vuln + test
├── Makefile                   # assemble / extract / vuln / test
├── requirements.txt           # pwntools, pytest, python-dotenv
├── Dockerfile                 # Isolated lab image (socat + toolchain)
├── docker-compose.yml         # lab + vulnerable TCP target services
├── .env.example               # TARGET_* + debug flags
├── README.md
├── glm-5.2.txt                # Signature: model that produced this revision
└── Gemini 3.1 Pro (High).txt  # Signature: prior v1 scaffolding (kept for diff)
```
