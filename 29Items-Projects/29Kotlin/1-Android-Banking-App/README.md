# 1-Android-Banking-App

A demo banking client for Android (Kotlin, Jetpack Compose, Room, Retrofit, Hilt) with a
Kotlin/Ktor mock backend providing accounts, payments, statements, and dual-layer rule-based
fraud detection (on-device + authoritative server-side). Educational/portfolio project —
**no real money movement** (sandbox scope only, see `docs/PROJECT-PLAN.md` non-goals).

## What works today (Phase 1 complete)

| Feature | Where |
|---|---|
| Login gate: demo PIN (`1234`) + biometric (`BIOMETRIC_STRONG`), 3-attempt lockout | `app/ui/login` |
| Accounts list (offline-first: Room cache, banner on network failure) | `app/ui/accounts` |
| Statements per account (tap an account card) | `app/ui/statements` |
| Transfers: account picker, amount validation, client balance pre-check, idempotent submit | `app/ui/transfer` |
| Fraud detection: identical rule set on device (UX gate) and server (authoritative, 403) | `app/fraud`, `backend/…/FraudDetectionService` |
| Encrypted token storage (`EncryptedSharedPreferences`), backup-rule exclusions | `app/security`, `app/res/xml` |
| Ktor backend: seeded demo data, idempotency replay, fraud-alert review queue | `backend/` |

## Prerequisites

- JDK 21 (`JAVA_HOME` must point at it — Gradle will not fall back)
- Android SDK (API 36; a `local.properties` with `sdk.dir` is generated by Android Studio)
- An Android device/emulator on API 33+ for running the app
- No Docker anywhere by design: the app ships via Google Play, the backend is a fat jar
  (`docs/TECH-NOTES.md` 3.1)

## Quick start (emulator loop)

Terminal 1 — start the mock backend on :8080:

```powershell
.\gradlew.bat :backend:run
```

Terminal 2 — install and run the app (or just press Run in Android Studio):

```powershell
.\gradlew.bat :app:installDebug
```

The app's **default** `BACKEND_BASE_URL` points at the docker-compose stack on the dev
remote PC (`http://192.168.0.104:8080/`) — installDebug works with zero flags when that
stack is up. For a backend running on the machine that also runs the emulator:

```powershell
.\gradlew.bat :app:installDebug -PbackendBaseUrl=http://10.0.2.2:8080/
```

On a **physical device**, point the app at your LAN IP instead:

```powershell
.\gradlew.bat :app:installDebug -PbackendBaseUrl=http://<your-lan-ip>:8080/
```

Demo credentials: PIN **1234** (shown on the login screen; it is a demo constant —
server-side auth is Phase 2 per `docs/PROJECT-PLAN.md`).

## Backend API

| Method | Path | Notes |
|---|---|---|
| GET | `/health` | liveness |
| GET | `/api/v1/accounts` | seeded demo accounts |
| GET | `/api/v1/accounts/{id}/transactions?limit=50` | newest first; `limit` 1..500; 404 unknown account |
| GET | `/api/v1/payments?accountId=…` | alias of the transactions list |
| POST | `/api/v1/payments` | requires `Idempotency-Key` header |

`POST /api/v1/payments` body:

```json
{"fromAccountId":"acc-1","payeeName":"Jane Doe","payeeIban":"UA…","amountMinor":1250,"currency":"EUR","reference":"Rent"}
```

Responses: `201` created (transaction JSON) · `200` idempotent replay (identical body) ·
`400` missing `Idempotency-Key` · `422` validation / unknown account / malformed JSON ·
`409` insufficient funds · `403` fraud-blocked (reasons in the message) · `415` wrong content type.

Every request carries an `X-Call-Id` correlation id (echoes an incoming header if present).

Try it:

```powershell
curl http://localhost:8080/api/v1/accounts
curl -X POST http://localhost:8080/api/v1/payments -H "Content-Type: application/json" -H "Idempotency-Key: demo-1" -d '{"fromAccountId":"acc-1","payeeName":"Jane Doe","payeeIban":"UA90","amountMinor":1500,"currency":"EUR"}'
```

## Run the stack with Docker (Ktor + PostgreSQL)

Persistent mode: Flyway applies `backend/src/main/resources/db/migration` on startup, and
data survives container restarts via the `pgdata` volume (unlike `:backend:run`, which is
the zero-dependency in-memory demo mode).

```powershell
.\gradlew.bat :backend:buildFatJar   # the jar is COPY'd into the image
docker compose up -d --build          # postgres:16-alpine + api, healthcheck-ordered
docker compose logs -f api            # Flyway + seed output
docker compose down                   # stop (add -v to wipe the database volume)
```

The API listens on `0.0.0.0:8080`. Point the app at whichever host runs the stack:

```powershell
.\gradlew.bat :app:installDebug -PbackendBaseUrl=http://<host-ip>:8080/
```

Note for remote Docker contexts: `docker compose build` ships the fat jar in the build
context to the remote daemon — nothing else leaves the repo. Two Docker-specific gotchas
are baked into the config: shadow's `mergeServiceFiles()` (Flyway's ServiceLoader registry
gets clobbered in fat jars otherwise — migrations silently don't run) and shipping the
migrations as real files (`FLYWAY_LOCATIONS=filesystem:/app/migration`).

## Testing

```powershell
# App JVM unit tests (fraud rules, ViewModels, money parsing/formatting)
.\gradlew.bat :app:testDebugUnitTest

# Backend tests (routes, idempotency, fraud rules — deterministic Clock)
.\gradlew.bat :backend:check

# Instrumented tests (Room + MockWebServer repository round-trip) — needs a device
.\gradlew.bat :app:connectedDebugAndroidTest

# Static analysis
.\gradlew.bat :app:detekt

# Everything CI runs
.\gradlew.bat :app:detekt :app:testDebugUnitTest :app:assembleDebug :backend:check
```

## CI/CD

- `.github/workflows/ci.yml` — every push/PR: detekt → unit tests → assembleDebug (app) and
  `:backend:check` in parallel jobs. Uploads the debug APK as an artifact.
- `.github/workflows/deploy-play.yml` — manual or on `v*` tags: decodes `KEYSTORE_BASE64`,
  builds a signed AAB, uploads to the Google Play **internal** track.
  Release signing is env-gated — local release builds stay unsigned unless
  `app/bank-release.jks` + `KEYSTORE_PASSWORD`/`KEY_ALIAS`/`KEY_PASSWORD` exist.

Copy `.env.example` values into CI secrets; never commit the filled file.

## Firebase (push notifications)

`TransactionPushService` renders FCM pushes once a real Firebase project exists:
create one, add an Android app with package `com.example.a1_android_banking_app`, download
`google-services.json` into `app/`, and apply the `com.google.gms.google-services` plugin **in
the same commit** (applying it without the JSON breaks every build — `docs/TECH-NOTES.md` 3.6 #3).
